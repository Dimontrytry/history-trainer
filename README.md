# History Trainer

Персональное устанавливаемое приложение для Windows 10/11 x64: библиотека исторического материала, тестирование, проверка знаний, локальные изображения, аналитика и полное резервное копирование. Интерфейс на русском языке.

## Состояние проекта

Product Specification 1.0 и стек Electron + React + TypeScript + SQLite утверждены пользователем. Реализована рабочая сборка разработки с настоящей локальной базой. Это ещё не законченный Windows-релиз: начальный исторический набор, согласованные фотографии и проверка установщика на Windows остаются открытыми.

Работают библиотека, темы, теги, наборы, связанные объекты, конспекты с локальными изображениями, массовый ввод с подтверждением, JSON/CSV, конструктор тестов, два Enter, итоговый разбор, самопроверка, окно знания из 20 оценок, статистика, медиадиагностика и полный ZIP-backup с восстановлением.

Фактические проверки и ограничения перечислены в [статусе реализации](docs/implementation-status.md). Тестовые объекты создаются только во временных профилях тестов; настоящая база ими не заполняется.

## Запуск разработки

Требуются Node.js 24 LTS и npm. Из каталога проекта:

```sh
npm ci
npm run dev
```

При `npm ci` проверяются SQLite и декодер изображений в реальном runtime Electron. Закреплённые better-sqlite3 13 и sharp используют готовые Node-API-модули; принудительная пересборка под Electron не нужна.

В Linux без дисплея предварительно установите Xvfb. В подготовленной облачной Debian-среде можно выполнить `bash scripts/setup-linux-display.sh`: пакет загружается с проверкой подписанного индекса и распаковывается в `.local`, без root-установки. `npm run dev` и E2E сами поднимают временный дисплей, если DISPLAY не задан. В Windows Xvfb не нужен.

## Проверки

```sh
npm run typecheck
npm run test:unit
npm run build
npm run test:integration
npm run test:e2e
npm run format:check
```

Интеграционные проверки запускаются после сборки и используют Electron, настоящую SQLite, реальные файлы и временные каталоги. E2E открывают настоящее окно приложения. В облачной инструментальной песочнице для X-сокетов может потребоваться запуск команды вне файловой песочницы; отключать sandbox в поставляемом приложении для этого не нужно.

После `npm run build` команда `npm start` открывает собранное приложение. `npm run start:cloud` запускает его на виртуальном дисплее с отдельным профилем разработки.

## Данные и резервные копии

Обычный запуск хранит данные в `app.getPath('userData')`, на Windows — в профиле пользователя `HistoryTrainer`, отдельно от программы. В настройках есть кнопка открытия каталога. Режим разработки использует отдельный `.local/development-profile`; это не каталог для постоянной пользовательской базы.

ZIP-backup содержит SQLite, конспекты, историю, оценки, настройки, наборы и локальные оригиналы изображений. Восстановление проверяет архив, хеши, схему и целостность, создаёт предварительную копию и переключает согласованное поколение базы. Источник изображения на рабочем столе после импорта не нужен.

JSON/CSV — обмен материалом. История и байты изображений переносятся через ZIP. JSON со ссылками на отсутствующие локальные изображения отклоняется. Совпадающие ID не перезаписываются молча. CSV предназначен для простых записей, не переносит конспекты, историю и медиатеку; указанные в нём ID тем должны существовать в целевой базе.

## Windows-сборка

На Windows x64:

```sh
npm ci
npm run dist:win
```

NSIS-установщик с русским интерфейсом появится в `dist`. Конфигурация не удаляет пользовательские данные при деинсталляции. В репозитории подготовлен [workflow проверок и Windows-сборки](.github/workflows/checks.yml). Он пока не запускался в GitHub; готовый EXE не заявляется полученным. Отдельная проверка установки/обновления на Windows 10 и 11 обязательна перед релизом.
