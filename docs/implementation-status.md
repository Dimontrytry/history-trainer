# Реализация: рабочая сборка разработки 0.1.0

Это фактический статус, а не заявление о завершении всех требований Product Specification 1.0. Код пока находится в рабочей копии; отправка в GitHub и запуск GitHub Actions не выполнялись.

## Реализованные возможности

| Область | Реализация |
| --- | --- |
| Desktop | Electron main, изолированный preload, sandbox renderer, отдельный процесс данных, типизированные и проверяемые команды |
| Хранение | SQLite, внешние ключи, WAL, транзакции, начальная схема v1 с контрольной суммой, отказ от подмены отсутствующей существующей БД пустой |
| Библиотека | Типы материала, дерево разделов/периодов/тем, создание и редактирование, поиск, фильтры, сортировка, выбор, удаление с подтверждением, массовое перемещение и теги |
| Связи | Теги, пользовательские наборы, связи учебных объектов и привязка к конспектам |
| Даты | Год, день в числовой/текстовой записи, интервал, век, половина/четверть века, приблизительность и BCE; календарь источника без автоматического пересчёта |
| Конспекты | Форматированный документ, заголовки, списки, локальные изображения и связанные объекты; внешние изображения не сохраняются как hotlink |
| Массовое добавление | Распознавание строк, пометка ошибок, исправление и явное подтверждение перед транзакцией сохранения |
| Обмен | JSON и простой CSV с предварительным просмотром; перенос JSON-связей с переназначением ID |
| Вопросы | Дата ↔ событие, правитель ↔ годы, термин ↔ определение, открытые вопросы, изображения, карты, четыре варианта и смешанные направления |
| Сессии | Отбор по области/конспекту/набору/объектам/ошибкам/слабому материалу, настраиваемое число, быстрый/случайный/экзаменационный/смешанный режимы |
| Подтверждение | Первый Enter — подтверждение с редактированием; второй фиксирует ответ один раз; повтор команды не создаёт дубль |
| Проверка | Нормализация, альтернативы, безопасная передача неоднозначных опечаток на разбор, структурные даты, частичный год, самопроверка и явные смысловые критерии |
| Результаты | Только после завершения теста; эталон, финальный ответ, оценка, основания, изменение знания и история |
| Знание | Последние 20 оценённых проверок направления; 1/0,5/0; среднее включённых направлений и объектов; неизученные не получают фиктивных попыток |
| Аналитика | Реальные показатели, темы/разделы, история активности, результаты, сохранённые снимки знания, графики и фильтр периода |
| Медиа | Локальная копия, файловый диалог и drag & drop, SHA-256, декодирование JPEG/PNG/WebP, источники, связи, запрет удаления используемого файла и диагностика |
| Backup | Проверяемый ZIP: SQLite, изображения и полный профиль; предварительный backup и переключение поколения при восстановлении |

Для развёрнутых ответов автоматическая проверка не претендует на понимание произвольного исторического текста. Полное совпадение с эталоном/альтернативой или воспроизведение всех явно заданных смысловых пунктов без неизвестных утверждений оценивается автоматически; неполные или неоднозначные случаи идут на самопроверку. Сходство фамилий само по себе не даёт правильный ответ.

## Проверки

Наборы проверок находятся в `tests/unit`, `tests/integration`, `tests/e2e`. Данные тестов явно синтетические и создаются во временных профилях.

- Unit: даты и эры, календарная валидность, нормализация, альтернативы, ложные совпадения, критерии, частичный балл, окно и уровни, разбор массового ввода, локальность изображений конспекта.
- Интеграция в Electron: настоящая SQLite, повторное открытие, снимки вопросов, идемпотентность, скрытие оценок до завершения, смешанные направления, выбор из вариантов, самопроверка, изображения, JSON/CSV, полный backup и отказы при ошибочных данных.
- E2E: настоящее окно, создание записи, два Enter с исправлением, повторный запуск, навигация, массовый ввод с ошибкой, drag & drop, фактическое декодирование локального изображения, редактор и сохранение конспекта.
- Dev smoke: Vite, настоящее окно Electron и обращение к SQLite через preload в отдельном временном профиле.
- Установка: `npm ci` действительно выполнена повторно; postinstall проверил SQLite и sharp в runtime Electron.

Точные результаты последнего прогона находятся в [отчёте проверок](validation.md): 43 unit-теста, 24 интеграционных сценария и два E2E, повторённые также на упакованном Linux-приложении. Успешная сборка JS не заменяет Windows-проверку. Наличие workflow не означает, что CI уже выполнился.

## Открытые обязательные этапы

1. **Начальное историческое наполнение 862–1551.** Не подготовлено и не загружено. Запросы к выбранным Wikimedia-источникам возвращают запрет сетевого прокси. Нужен доступ к источникам, затем проверенный перечень и согласование до включения в базу. Случайных исторических записей вместо него нет.
2. **Фотографии пяти персонажей.** Не получены и не согласованы. Интерфейс позволяет назначить собственные локальные файлы; неполученные фотографии не подменяются выдуманными портретами или внешними URL.
3. **Windows EXE и проверка на Windows 10/11 x64.** Подготовлены конфигурация NSIS и workflow. Сборка/установка на Windows ещё не выполнялись. Linux-проверка не подтверждает Windows-релиз.
4. **Завершение приёмки.** Проверить полный сценарий установки, обновления с пользовательской базой, масштабирование Windows и реальные исторические карты/портреты. Модели, на которых есть только синтетические технические проверки, не объявляются проверенными на настоящем историческом корпусе.

## Известная особенность Linux-среды

Sharp предупреждает о совместимости Electron/Linux; при декодировании наблюдаются сообщения GLib. Причина описана в [официальной документации sharp](https://github.com/lovell/sharp/blob/main/docs/src/content/docs/install.md#electron-and-linux): Electron экспортирует символы системной glib, которые могут конфликтовать с libvips. JPEG/PNG/WebP и восстановление с изображениями функционально проверены, предупреждения не подавлялись. Это ограничение Linux-проверки; о поведении на Windows вывод делается только после Windows-прогона.

## Отличия физической схемы v1 от логической модели

Схема находится в `src/infrastructure/storage/database.ts`. Факты хранятся типизированно; источники первого варианта — поля описания происхождения у материала и ассета. Отдельный реестр начальных контент-пакетов появится вместе с проверенным корпусом. Текущий прогресс рассчитывается по истории, а снимки изменения хранятся в оценках и `knowledge_snapshots`; отдельных кэш-таблиц всех проекций пока нет. Формула одна, согласованной версии; будущая смена формулы или схемы требует отдельной миграции, а не молчаливого пересчёта.

Точный список поддержанных полей JSON/CSV определяется схемами приложения; ZIP предназначен для полного переноса. Размер файла обмена ограничен 20 МБ, изображения — 50 МБ и 40 млн пикселей, распакованного backup — 2 ГБ. Это явные ограничения текущей реализации.
