# Структура проекта и план реализации

Основание: утверждённая Product Specification 1.0 и предлагаемая архитектура. Статус: реализация ведётся. Основные модули, команды и тесты созданы; актуальная проверенная часть и открытые этапы перечислены в implementation-status.md. Windows-установщик ещё не получен.

Фотографии персонажей и исторический контент поставляются только после проверки происхождения и самих файлов. Файлы `content` в дереве — запланированные результаты, а не уже подготовленная база.

Зависимости направлены от UI к контрактам, от сценариев к предметным модулям и интерфейсам хранения. Предметные модули не зависят от инфраструктуры. Все системные операции проходят через сценарии приложения.

## 3. Этапы

Ни один промежуточный этап не объявляется полноценным продуктом. Полный состав первой версии не сокращается молча до первого рабочего экрана.

### Этап 1. Проверка стека и каркас

Результат: запускаемое desktop-окно, изолированный preload, типизированная команда к процессу данных, настоящая SQLite и локальный ассет. Закреплены версии и lockfile.

Проверки:

- Запуск Electron и загрузка SQLite-модуля в том же runtime, в котором он будет работать.
- Запись, закрытие, повторное открытие БД и чтение сохранённой записи.
- Декодирование и чтение тестового изображения из временного пользовательского каталога.
- Разделение Node-unit и Electron-integration тестов без конфликта ABI.
- Ранний Windows x64 smoke и пробная упаковка NSIS, чтобы не откладывать платформенные проблемы до завершения UI.

Тестовый объект и изображение принадлежат developer fixtures, а не настоящей пользовательской базе. В продуктовый интерфейс не добавлять обещанные, но неработающие кнопки.

### Этап 2. Хранилище, миграции и сохранность

Результат: схема библиотеки, источников, дат, медиа и истории; путь данных вне установки; миграции и восстанавливаемые операции с файлами.

Проверки: ограничения связей, транзакции, неудачная миграция с сохранением исходной базы, повторное открытие и сбои в ключевых точках записи.

### Этап 3. Даты, библиотека и конспекты

Результат: все согласованные форматы дат, дерево, поиск, фильтры, CRUD, массовое перемещение/теги, редактор конспектов и связанные изображения.

Проверки: эры и отсутствие нулевого года; римские века и части века; приблизительность без скрытого допуска; равенство текстового и числового дня; изменение и удаление материала; чтение после перезапуска. Проверить сохранение форматированного документа и ссылок на медиа.

### Этап 4. Массовый ввод и обмен

Результат: текстовый ввод с предварительным разбором, редактированием строк и подтверждением; JSON и CSV с проверкой версии и содержимого.

Проверки: неоднозначные строки, интервалы с тире внутри даты, кавычки и переносы CSV, конфликт идентификаторов, повторный импорт и отсутствие частичного применения при ошибке транзакции. Экспорт/импорт сравниваются по содержимому и связям, а не по существованию файла.

### Этап 5. Движок вопросов и тестирование

Результат: все направления и режимы первой версии, настройка отбора и количества, неизменяемые вопросы сессии, окончательные ответы и итоговый разбор.

Проверки: первый Enter не создаёт попытку; редактирование возможно до второго; второй сохраняет актуальный ответ ровно один раз; при повторной доставке нет дубля. До завершения не раскрываются эталоны. Изменение карточки не меняет начатый вопрос. Проверить карты, изображения, смешанный тест и нехватку данных для вариантов.

### Этап 6. Проверка ответов, знания и аналитика

Результат: нормализация, альтернативы и синонимы, структурная проверка дат, осторожная обработка опечаток, два режима развёрнутых ответов, окно 20, уровни, ошибки и настоящие графики.

Проверки:

- Ё/Е, регистр, пробелы и допустимые альтернативы.
- Сходные фамилии, отрицания и изменённые числа не принимаются только по текстовой близости.
- Год при ожидаемом дне — 0,5; неверный явно указанный день не получает этот балл автоматически.
- 1 правильный = 5%; 1 частичный = 2,5%; 19 правильных + 1 частичный = 97,5%; смена окна и границы 50/70/90/97.
- Направления учитываются отдельно, непроверенные дают ноль без ложных попыток; теги не удваивают вес.
- Отложенная оценка и её ревизия не считаются двумя проверками; проекции воспроизводятся по истории.
- Пустая база и отсутствие оценок не показывают выдуманную статистику.

### Этап 7. Полный backup, восстановление и медиадиагностика

Результат: согласованный ZIP с полной базой и ассетами, предварительная копия перед восстановлением, безопасное переключение поколения и диагностика медиа.

Проверки: восстановление в пустой временный профиль и сравнение объектов, связей, настроек, истории, прогресса и байтов изображений. Повреждённые, неполные, неподдерживаемые и опасные архивы не меняют рабочую базу. Прерывания до и после переключения не оставляют смесь двух поколений. Проверить backup при наличии WAL и одновременной попытке изменения медиатеки.

### Этап 8. Историческое наполнение и портреты

Результат: проверенный перечень основных событий России 862–1551, основная линия правителей с повторными правлениями и полными интервалами, источники и согласованные локальные портреты пяти персонажей.

Перечень материала и варианты фотографий предъявить до включения в настоящую базу. Если источник недоступен, данные спорны или изображение не получено, назвать проблему и запросить нужный материал/решение; не использовать фиктивное наполнение.

Проверки: соответствие согласованному перечню, источники фактов, отсутствие дублей при повторном применении набора, сохранение пользовательских правок, хеши и реальное декодирование портретов. Учебные примеры из ТЗ сами по себе не считаются готовой исторической базой.

### Этап 9. Визуальная доводка и Windows-релиз

Результат: законченная навигация, клавиатура, focus и reduced motion, ранги с проверенными портретами, установщик и проверенный основной цикл работы.

Проверки на Windows 10/11 x64: установка → добавление/импорт → изображения → тест → разбор → перезапуск → аналитика → backup → восстановление → обновление с сохранением данных. Проверить кириллицу в путях, масштабирование окна и дисплея, отсутствие ошибок процессов и сломанных изображений.

Подготовить инструкции установки, обновления и восстановления. Без фактической Windows-проверки этап не объявляется пройденным.

## 4. Запланированные команды

Ниже приведены команды текущего проекта. Команды созданы. npm ci, dev, typecheck, unit, build, integration и E2E проверяются в Linux; dist:win остаётся непроверенной до Windows-прогона. Инструкции запуска находятся в README.

| Команда | Назначение |
| --- | --- |
| `npm ci` | Установить закреплённые зависимости и подготовить native-модули для Electron |
| `npm run dev` | Запустить desktop-приложение с разработкой renderer |
| `npm run typecheck` | Проверить main, preload, процесс данных, домен и UI |
| `npm run test:unit` | Чистые предметные тесты в Node |
| `npm run test:integration` | База, файлы, миграции и backup в Electron runtime |
| `npm run test:e2e` | Реальные сценарии приложения через Playwright |
| `npm run build` | Собрать все точки входа приложения |
| `npm run dist:win` | Собрать Windows x64 установщик на Windows runner/машине |

## 5. Среда и автоматизация

Облачная Linux-среда уже изолирована: использовать существующий checkout; не создавать worktree без запроса пользователя. Тестовые профили и developer fixtures хранятся отдельно от настоящих пользовательских данных.

Будущие CI-задачи:

- Linux: установка, typecheck, чистые тесты, сборка и интеграция с настоящей SQLite; Electron UI при подготовленном дисплее.
- Windows x64: установка native-зависимостей под Electron, интеграция, e2e и NSIS-артефакт.
- Windows 10 и 11: финальный сценарий установки и обновления проверяется отдельно; обычный hosted runner одной версии не подтверждает другую ОС.

Workflow-файлы можно подготовить в репозитории, но их наличие не означает запуск CI. Push, выпуск GitHub Release и публикация не выполняются автоматически из-за создания конфигурации.

После появления реально работающих команд обновить README и сохранить проверенные install_script/start_skill для облачной среды. Не сохранять как проверенные инструкции команды из этого плана до их исполнения.
